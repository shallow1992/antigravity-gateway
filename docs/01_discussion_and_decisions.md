# 01. ディスカッション記録と技術選定の背景

本書は、Antigravity を Slack/Discord から利用するための仕組みを構築するにあたり行われたディスカッション、比較検討したパターン、および意思決定の経緯を記録したものです。

---

## 1. 検討の背景と課題

* **背景**: Antigravity (AGY) を日常的に使用する Slack や Discord から操作したい。
* **現状**: 公式には既製品としての「Slack App」や「Discord Bot」は提供されていない。
* **利用可能な公式コンポーネント**:
  * **Antigravity Python SDK (`google-antigravity`)**: プログラムからエージェントを起動・制御可能な公式SDK。
  * **Antigravity CLI (`agy`)**: ターミナル用CLI。
  * **MCP (Model Context Protocol)**: ツール統合規格。

## 3. インフラ・実行環境の議論

### Q1. サーバーは「ローカル」と「クラウド」どちらでもいいのか？
* **結論**: **どちらでも可能**。
* **ローカル（開発者PC）**:
  * 自分のPC上のローカルリポジトリや環境変数を直接編集できる。
  * 追加のクラウド費用が0円。
  * Slackの **Socket Mode** を使えば、グローバルIPやポート開放（ルーター設定）なしで動作。
* **クラウド（VPS / VM / コンテナ）**:
  * 24時間365日安定して稼働（チーム全員で共有可能）。
  * サーバー環境をサンドボックス化して安全に分離しやすい。

### Q2. 常駐プロセスである必要があるのか？
* **結論**: **リアルタイムなチャット体験を実現するには「常駐（Long-running）」が基本**。
* **常駐が必要な理由**:
  1. **WebSocket（Socket Mode）の維持**: 外部からのメッセージを即座に受信するため。
  2. **リアルタイム進捗（Thinking / ツール実行）**: エージェントの思考過程をSlackスレッドに逐次反映するため。
  3. **Slackの3秒ルール**: Slack Events API は3秒以内に `200 OK` を返さないとタイムアウトしてリトライする。サーバーレスで非同期構成にするにはキュー（SQS/PubSub等）や別ワーカーが必要になり複雑化する。
  4. **起動オーバーヘッド（コールドスタート）の回避**。

## 4. UI/UXとフォーマットの課題と解決策

### 課題A: Slack / Discord の Markdown 方言・崩れ
* **問題**: Slack は `*太字*`, `<url|text>` を採用しており、標準の `# 見出し`, `**太字**`, `[text](url)`, テーブル記法 `| a | b |` が崩れる。
* **解決策**:
  * 送信前に自動コンバーターを通して Slack の `mrkdwn` / Block Kit 形式へ変換。
  * テーブルやDiffは等幅コードブロック（` ``` `）やアスキーアート形式で囲む。

### 課題B: アーティファクト（Plan, Walkthrough, Diff）がチャット欄で読みにくい
* **問題**: Antigravity の強みである長文の Implementation Plan や Mermaid 図をチャットに流すと画面を埋め尽くして著しく可読性が落ちる。
* **検討した解決策**:
  1. **軽量Webビューワー方式 (FastAPI + 共有URL)**:
     * チャットには「要約＋リンク」だけを流し、詳細はブラウザでGitHubライクなダークモードUIで閲覧。
     * ローカル時は **Cloudflare Tunnel**（無料）を使えばポート開放なしでHTTPS URLが即時発行可能。
  2. **Slack Canvas / ファイル添付 (`files.upload_v2`) 方式**:
     * `.md` や `.diff` ファイルとしてスレッドに添付し、インラインプレビューさせる。
  3. **GitHub Issue / PR 連携方式**:
     * プランやDiffをGitHub側に作成し、リンクで確認。

## 5. 最終決定事項

1. **リポジトリ名**: `antigravity-gateway`
2. **採用アーキテクチャ**: **Python SDK (`google-antigravity`) + Slack Bolt (Socket Mode)**
3. **開発アプローチ**:
   * **フェーズ 1**: 最小構成＆セキュリティ最優先（ローカル常駐、Socket Mode、特定ユーザーのみ許可、安全な権限制御）
   * **フェーズ 2**: 軽量 Web ビューワー（FastAPI + Cloudflare Tunnel）の統合によるリッチな Artifacts 閲覧・承認
   * **フェーズ 3**: クラウドデプロイ対応（Docker化）および Discord への拡張
